Build an infinite-canvas research workspace app.

Core idea:
A visual thinking and research workspace where users create movable cards/nodes, connect them with arrows, attach sources or files, and write rich formatted text inside each card. 
It should support workflows like literature review, market research, investigative mapping, note synthesis, project planning, and knowledge organization. 
The text must behave like real document text(with highlightings and reflowing), not painted canvas text.

Primary requirements:

1. Infinite canvas
- Pan and zoom.
- Drag cards freely.
- Select, move, resize cards.
- Multi-select cards.
- Snap/grid optional.
- Save and reload full board state.

2. Rich text cards
Each card must contain an actual editable rich-text editor, not canvas-rendered text.
Text must:
- wrap/reflow automatically inside the card when resized.
- support bold, italic, underline.
- support real inline highlights.
- support links.
- support bullet lists.
- preserve formatting after save/load.
- be selectable and copyable like normal text.
- default = view(read) mode, double click/click pencil button(found in each text card) to edit.

Important:
Do NOT implement text as drawn canvas labels.
Do NOT implement highlights as rectangles painted over text.
Use HTML/contenteditable or a proper rich-text editor like TipTap/ProseMirror/Lexical.

3. Node/card types
Keep only base card types:
- Text card
- Image card
- Table card (spreadsheet-like)

Do not hardcode workflow-specific card types (person, evidence, company, etc.).
Users define meaning through tags and tag properties.

Each card should have:
- id
- type
- title
- rich text body
- position x/y
- width/height
- tags
- optional source URL
- optional attached image
- optional metadata object for domain-specific fields
- created/updated timestamp

Tag model:
- tags: list of tag IDs on each card
- tagDefinitions: global tag config for board (name, color, icon, group, optional properties schema)
- tagProperties: optional per-card values for tag properties

Example tag properties:
- confidence: low / medium / high
- status: draft / review / verified
- owner
- priority
- date

4. Connectors
- Draw arrows/lines between cards.
- Connectors should stay attached when cards move.
- Connector labels should be editable.

5. Research workflow
User should be able to:
- paste screenshots/images.
- paste URLs.
- add short source notes.
- define and edit tags.
- define properties for each tag.
- add property values to cards based on selected tags.
- filter board by tag, tag group, and tag property values.
- save named filter views (for example "Only high confidence" or "Only pending review").

6. Visual style
- Clean research workspace UI.
- Cards should be readable and document-like, with optional visual themes.
- Arrows between related ideas, sources, and entities.
- Optional investigation-style or red-string theme can exist as a preset, but the default should be neutral and broadly usable.
- Search bar at top.
- Left sidebar for board outline / card list.
- Right inspector panel for selected card metadata.

7. Table card — Excel/CSV import library
For client-side import (browser):
- Use SheetJS (xlsx package, MIT license, ~500KB, pure JS).
- Handles xlsx, xls, ods, csv.
- Import runs entirely in the browser — no server round-trip.
- Parse first sheet into rows/columns, store in card metadata.
- Render editable table UI on demand (edit mode only).

For server-side Excel generation (export from backend):
- Use openpyxl (Python, MIT license, lightweight).
- openpyxl cannot run in the browser; it is strictly for backend generation.
- Use it if users need to download a full xlsx export of a table card or board summary.

Both can coexist: SheetJS handles import in browser, openpyxl handles export from Python backend.
Use a JSON-serializable board format.

8. Persistence
Start simple:
- localStorage or IndexedDB for browser version.
Better:
- SQLite backend later.
- Export/import board as JSON.
- Export board as PNG/SVG/PDF.
- Export selected cards as Markdown.

Generalization principle:
- Keep the core schema generic.
- Put workflow-specific meaning into tags, tag properties, and filters.
- "Investigation board" should be one starter template, not the product definition.

9. Recommended stack
python based, performant, free/open source.
No JS in backend or react like frontend stacks that requrire building either.

Important architecture decision:
Canvas library handles movement, zoom, nodes, and edges.
Rich text editor handles the text inside each node.
Do not let the canvas library own rich text behavior.

10. MVP scope
Build first:
- Infinite canvas
- Rich text card with reflowing text
- Real inline highlight
- Drag/resize card
- Connect cards with arrows
- Save/load JSON
- Export/import JSON
- Base card types only (text/image/table)
- Tag definitions with configurable properties
- Tag-based filters and saved views

Avoid in MVP:
- Collaboration
- AI
- user accounts
- complex permissions
- cloud sync
