# Nightcraft — Local Dev Stack

Run the **entire Nightcraft app suite** on your machine **without polluting your
global environment**:

- **PostgreSQL + Redis** run in Docker (exposed on loopback `127.0.0.1:5432` / `:6379`).
- **Python apps** run on the host inside **`uv`-managed, isolated virtualenvs**.
  `uv` downloads and manages its own Python 3.12 — no system `python3`, `pip`, or `apt` required.
- Everything is driven by **re-runnable shell scripts**, so the same flow works on a
  fresh machine later.

> No `apt`/`sudo` installs of `python`, `postgresql-client`, `redis-tools`, or `node`
> are performed by these scripts.

---

## Architecture

```
 Host (scripts + uv venvs)                 Docker (infra only)
 -----------------------------             -----------------------------
 service-auth    (uv venv :5100)  ─┐
 app-radio       (uv venv :5333)  ─┤
  app-artsy       (uv venv :5600)  ─┼─▶ 127.0.0.1:5432  postgres  (auth_db, radio_db,
  app-note        (uv venv :5900)  ─┤                                  neera_db, notestack_db)
 app-game        (uv venv :5800)  ─┤             :6379  redis    (game sessions)
 app-landing     (uv venv :5400)  ─┤
 app-admin       (uv venv :5500)  ─┘
 app-mindmap     (uv venv :8000, uvicorn)
```

Apps connect to the infrastructure over the **localhost published ports** — no Docker
networking or service-name DNS required.

## Prerequisites (one-time, manual)

| Requirement | Why | Install |
|---|---|---|
| **Docker** | Runs Postgres + Redis | <https://docs.docker.com/engine/install/> (or `curl -LsSf https://get.docker.com \| sudo sh`) — daemon must be running |
| **`uv`** | Builds isolated Python venvs (auto Python 3.12) | Installed automatically to `~/.local/bin` by `check-deps.sh`; or manually: <https://docs.astral.sh/uv/getting-started/installation/> |

That is the **only** host setup. No system Python, no `sudo` package installs.

Optional: add `~/.local/bin` to your `PATH` so `uv` is available in every shell:
```bash
export PATH="$HOME/.local/bin:$PATH"
```

## Quick start

```bash
# Full setup: infra + dbs + venvs + schema + seed + start all services
bash dev-setup/nightcraft-dev-setup.sh

# Wipe all .nightcraft-* runtime state and rebuild from scratch
bash dev-setup/nightcraft-dev-setup.sh --clean

# Just stop everything
bash dev-setup/shutdown.sh
```

When it finishes you should see all services up, seed users created, and a list of URLs.

### Useful flags

| Flag | Effect |
|---|---|
| `--skip-infra` | Assume Postgres/Redis are already running |
| `--skip-deps` | Skip `uv` venv builds |
| `--skip-init` | Skip database schema initialization |
| `--skip-seed` | Skip seed users / OAuth clients |
| `--no-start` | Stop before launching services |
| `--clean` | Remove all `.nightcraft-*` state, then run |
| `--sudo` | Re-run the whole script under `sudo` (optional) |

## What each script does

All scripts live in `dev-setup/` and source `dev-setup/common.sh`, which defines the
canonical paths and Docker helpers (`wait_for_pg`, `wait_for_redis`).

| Script | Responsibility |
|---|---|
| `check-deps.sh` | Verify Docker is reachable; install `uv` (non-root) if missing. **No apt/sudo.** |
| `start-infra.sh` | `docker compose up` Postgres + Redis, wait until healthy. |
| `setup-dbs.sh` | Create DB roles + databases in Postgres from `platform-infra/prod-debian/postgres/*.sql` (idempotent). |
| `install-env.sh` | Copy `env-templates/*.env` into `.nightcraft-env/`, substituting `${NIGHTCRAFT_SHARED_DIR}`. |
| `install-deps.sh` | Build an isolated `uv` venv per app and install its `requirements.txt` (+ `gunicorn`, `psycopg[binary]`). |
| `init-dbs.sh` | Initialize each app's schema idempotently (see below). |
| `seed-data.sh` | Create seed users (`seeduser`/`seedadmin`) and dev OAuth clients via the auth service. |
| `start-all.sh` | Launch every service in the background from its venv, writing `.pid` files. |
| `stop-all.sh` | Kill running service processes. |
| `stop-infra.sh` | `docker compose down` (data volume is preserved). |
| `status.sh` | Print service + container + runtime-dir status. |
| `shutdown.sh` | `stop-all.sh` + `stop-infra.sh`. |
| `nightcraft-dev-setup.sh` | Orchestrator that runs the steps above in order. |

**Orchestration order:** `check-deps → start-infra → setup-dbs → install-env →
install-deps → init-dbs → seed-data → start-all`.

## Runtime layout

Everything generated by the scripts lives next to the repo root and is **gitignored**:

```
.nightcraft-env/      # resolved .env files (copied from env-templates/)
.nightcraft-venvs/    # one uv venv per app (uv-managed Python 3.12 lives in ~/.local/share/uv)
.nightcraft-shared/   # per-app persisted data (radio instance, game emulator db, etc.)
.nightcraft-logs/     # per-run + per-service logs
```

The `env-templates/*.env` files **are** tracked (they contain only literal dev values
plus the `${NIGHTCRAFT_SHARED_DIR}` placeholder).

### Database credentials (dev)

| DB | Role | Password |
|---|---|---|
| `auth_db` | `auth_app` | `auth_app_db_2026_prod_secret` |
| `radio_db` | `radio_app` | `radio_app_db_2026_prod_secret` |
| `neera_db` | `neera_app` | `neera_app_db_2026_prod_secret` |
| `notestack_db` | `notestack_app` | `notestack_app_db_2026_prod_secret` |

Connection string form (SQLAlchemy): `postgresql+psycopg://<role>:<pw>@127.0.0.1:5432/<db>`.
NoteStack uses **raw `psycopg`**, so its `DATABASE_URL` uses the plain
`postgresql://` scheme.

## Schema initialization

All Postgres-backed apps create their tables inside their Flask app factory
(`db.create_all()` / `initialize_db()` / `init_db()` in `create_app()`). `init-dbs.sh`
therefore drives schema creation by **importing each factory with the app's dev env
loaded** — this reuses the app's own, authoritative schema logic and is safe to re-run.

## Running the test suite against the stack

The isolated Postgres is reachable from any app venv, so DB-backed tests run without a
system client. Example for `service-auth`:

```bash
# point the test at a dedicated (empty) database
docker exec nightcraft-postgres psql -U postgres \
  -c "CREATE DATABASE auth_test_db OWNER auth_app ENCODING 'UTF8';"

export TEST_DATABASE_URL="postgresql+psycopg://auth_app:auth_app_db_2026_prod_secret@127.0.0.1:5432/auth_test_db"
export NIGHTCRAFT_SHARED_DIR="$PWD/.nightcraft-shared"

.nightcraft-venvs/service-auth/bin/python -m pytest \
  service-auth/tests/test_core_endpoints.py -q
```

> Use a **separate** test database (not the seeded `auth_db`) so the seed users/clients
> don't collide with test fixtures. Some tests in the suite re-insert the same
> `admin-user` / `radio-app` fixtures without per-test cleanup; those are pre-existing
> test-isolation issues and are unrelated to the dev stack.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `check-deps.sh` says Docker not reachable | Start the daemon (`sudo systemctl start docker`) or pass `--install-docker`. |
| `uv: command not found` in a new shell | `export PATH="$HOME/.local/bin:$PATH"`. |
| Service won't start / port already in use | `bash dev-setup/stop-all.sh`, then retry. |
| NoteStack tables missing | Re-run `bash dev-setup/init-dbs.sh` (idempotent). |
| NoteStack errors on connect | Ensure its `DATABASE_URL` uses `postgresql://` (raw `psycopg`), not `postgresql+psycopg://`. |
| Game 500 / `unable to open database file` | Ensure `GAME_SHARED_DIR` is set (template default points under `.nightcraft-shared/app-game`, created at start). |
| Paths with spaces break `source` of env files | Values referencing the shared dir are quoted in the templates; keep them quoted if you edit. |
