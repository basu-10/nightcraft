# Alfred — AI Workspace MVP Plan (Ask Alfred + Library)

## Feasibility summary
Feasible and low-risk, built on the **existing nightcraft stack** — the live apps in this
repo (`app-artsy`, `app-radio`, `app-note`, `service-auth`) already prove every
required capability (Flask+psycopg+Postgres, OAuth SSO adapter, per-app admin +
`AppSetting` store, nginx subpath, Docker/systemd provisioning).

Alfred's architecture is derived from the **provided product spec** (the Asset / Operation /
Planner / Workflow / Evidence / Relation vocabulary and principles P1–P7), **not** from any
prior product. The retired SeekSage (formerly `app-researchAgent`) and Butler code names are
intentionally **not** used as a reference: SeekSage was a web-research ReAct agent with different
objectives, whereas Alfred is built fresh from the ground up to surpass both SeekSage and Butler
as a persistent, immutable, provenance-tracked Asset library with RAG over it and in-conversation
artifact editing. Where this plan cites a "precedent," it means a **live** repo pattern (auth
adapter, settings service, provisioning), never the retired products.

The RAG vs non-RAG requirement is **not** a special problem: it is two tool categories
(`library_search` for RAG, `web_search`/`wiki`/`visit_url` for non-RAG) that the
spec's Planner routes between per step.

## Confirmed decisions
- **Planner**: Hybrid — LLM emits an explicit high-level plan (phases) shown to the user; within each phase a ReAct-style executor dynamically picks tools (library_search vs web). Maps to spec P6 (Planner decides / Workflow executes).
- **RAG infra**: `pgvector` on existing Postgres 16 + **OpenRouter** for both LLM and embeddings (`EmbeddingProvider`). Verified: OpenRouter exposes an OpenAI-compatible `POST /api/v1/embeddings` endpoint with models like `openai/text-embedding-3-small` (1536-d), `openai/text-embedding-3-large`, `qwen/qwen3-embedding-8b`. Default embedding model = `openai/text-embedding-3-small`; admin-configurable.
- **Frontend**: Flask + Jinja (server-rendered), live updates via **polling a `RunEvent` table** (`POST /alfred/api/runs` starts a background worker thread and returns `run_id`; `GET /alfred/api/runs/<id>/events` returns ordered events). Chosen because it is nginx/proxy-friendly and avoids streaming-buffering config; reuse the ecosystem auth adapter. Not borrowed from any deprecated product.
- **MVP scope**: Ask Alfred mode + Library mode only. Search/Editor deferred as separate modes, BUT the core differentiating feature — **drag-drop a file into the conversation and ask Alfred to change a paragraph / reformat** — is a first-class MVP capability inside Ask Alfred (not deferred).
- **MVP generated artifact**: Report (markdown/HTML) stored as an immutable Asset. Ingestion of uploaded files + web imports is required as Library *inputs* for RAG.
- **Drag-drop edit output**: User drops a file → it becomes an immutable Asset AND attaches to the composing message. The next instruction ("change the intro paragraph", "reformat as bullets") routes to a transform operation that emits a **new markdown/HTML Report Asset** that is `version_of` + `derived_from` the source (P1 immutability, P4 provenance). Original is never modified. Re-emitting the *original binary format* (.docx/.pptx round-trip) is deferred.
- **Settings live on the admin side only**: embedding model, agent/ReAct LLM model, max steps, chunk size, top-k, etc. are configured in a per-app Alfred admin page. Normal users never see model/embedding controls.

## Reused stack / provisioning (no new paradigm)
Grounded in the **live** repo (not deprecated code):
- Flask 3 + Flask-SQLAlchemy + psycopg, Postgres 16 (+pgvector), Redis — same as `app-radio`/`app-note`.
- Auth adapter pattern from `app-artsy/neera/auth` (`local_auth`/`sso_auth`/`current_user`, `get_current_user()` → `user_id`, `AUTH_MODE`).
- Per-app admin/settings pattern from `app-radio/devradio` (`AppSetting` model + `services/settings.py` + `crypto.EncryptionService`, `@admin_required` blueprint).
- nginx subpath routing **now via a generated `on-demand.conf` driven by `products.yml`** (see §10), an always-on **Runtime Manager** (`nightcraft-runtime-manager.service`) that cold-starts `on_demand` apps on first request and auto-stops them after an idle timeout, plus a branded loading page. Neera/Artsy is the reference `on_demand` app to copy.
- Docker Compose (`dev-setup`) remains the local-dev path; the Runtime Manager/on_demand flow is production-only.
- The **product spec** is the source of truth for architecture (Assets immutable, Evidence provenance, Planner≠Workflow, relation types). No deprecated product informs these decisions.

## Architecture / modules (new app: `app-alfred`)

### 1. Auth adapter (reuse pattern from `app-artsy/neera/auth`)
- `app/alfred/auth/{local_auth,sso_auth,current_user}.py`; rest of app calls `get_current_user()` → `user_id`.
- Env: `AUTH_MODE`, `AUTH_SERVICE_URL`.

### 2. Data model (SQLAlchemy, immutable Assets) — `models.py`
- **Asset**: `id, content_hash (unique), content_type, storage_ref, metadata_json, lineage_json, user_id, workspace_id, created_at`. Identity = content hash (dedupe on ingest). Never updated; new version = new Asset. **Scoped per-user for MVP**: RAG/retrieval and the Library UI filter by `user_id` (private library). `workspace_id` is reserved for future shared workspaces but unused in MVP.
- **AssetRelation**: `from_id, to_id, relation_type` (only spec types: derived_from, version_of, references, cites, supports, contradicts, contains, depends_on, generated_by).
- **Evidence**: `id, source_asset_ids[], payload_json, run_id, created_at`. Provenance mandatory (P4) — reject Evidence with empty source list.
- **AgentRun**: `run_id, user_id, workspace_id, session_id, plan_json, status`.
- **RunEvent**: streaming events (`EVT_PLAN`, `EVT_LLM_*`, `EVT_TOOL_*`, `EVT_ARTIFACT`).
- **ChatSession / Message**: conversation per user.
- **AssetEmbedding**: `asset_id, chunk_index, embedding vector, model` (pgvector `halfvec`/`vector`). Stored per `AssetChunk`, not directly on Asset, so a model/embedding-dimension change only requires re-embedding chunks.
- **AssetChunk**: `asset_id, chunk_index, text, token_count` — extracted text chunks (source of truth for embeddings + for the edit/transform operation that loads Asset text).

### 3. Providers (capability wrappers, no business logic) — `providers/`
- `LLMProvider` (OpenRouter chat completions), `EmbeddingProvider` (OpenRouter embeddings), `WebSearchProvider` (DuckDuckGo/News/ArXiv, rate-limited). These are **new** providers written for Alfred; no deprecated product is referenced.

### 4. Planner (hybrid) — `agent/planner.py`
- `plan_goal(goal, library_summary)` → structured JSON phases, e.g. `[{phase:"retrieve", tools:["library_search"]}, {phase:"research", tools:["web_search","wiki_search","visit_url"]}, {phase:"synthesize"}, {phase:"generate_report"}]`. Persisted as `AgentRun.plan_json` and streamed to UI (`EVT_PLAN`).
- **RAG vs non-RAG routing**: the Planner inspects the goal plus a `library_summary` (counts + headlines of the user's available Assets). If the library likely contains the answer it emits a `retrieve` phase whose allowed tool is `library_search` (RAG path); otherwise it emits a `research` phase with web tools (non-RAG path). Both can appear in one plan (e.g. retrieve from library, then web for gaps). This is exactly how the spec's "Alfred decides when to search the library vs the web" is realized.

### 5. Workflow executor — `agent/graph.py` (LangGraph)
- LangGraph is chosen because its graph + checkpointer model maps cleanly onto the spec's Planner/Workflow separation (P6). It is a general library, **not** derived from any prior product.
- Processes the Planner's phases **sequentially**. Within each phase it runs a ReAct loop: the LLM may call only that phase's `allowed_tools`; the loop ends when the LLM signals phase completion or `max_steps` (from admin settings) is hit, then advances to the next phase. This keeps the Planner/Workflow separation (P6): the Planner fixed *what may happen*; the executor *dynamically chooses* within those bounds.
- Nodes: `planner_phase_node` (LLM + allowed tools for current phase), `tool_executor`. Conditional edge routes between them; `max_steps` budget per phase.
- **Tools**: `library_search` (RAG), `web_search`, `wiki_search`, `visit_url` (also imports fetched page as Asset), `save_report` (creates Report Asset + `derived_from` relations + Evidence with provenance), `transform_asset` (edit/rewrite an attached Asset → new `version_of` Report Asset).
- Checkpointer: Postgres/Redis-backed (persistent across restarts).

### 6. RAG retrieval — `rag/`
- Ingest: parse (pdf/text/md) → chunk → `EmbeddingProvider.embed` → store `AssetEmbedding`.
- `library_search(query)` → embed → pgvector cosine top-k (filtered by `user_id`) → return Evidence with `source_asset_ids`. Each user only retrieves their own Assets.

### 7. Drag-drop file ingest + in-conversation edit (CORE feature) — `ingest/` + `agent/`
- **Drag-drop**: JS dropzone in the Ask view POSTs the file to `/alfred/api/ingest` → creates an immutable Asset (`content_hash` dedupe) → the file is shown as an attached chip on the composing message and also appears in the Library. Works with Flask+Jinja (server renders page; JS handles DnD + upload + polling).
- **Edit/transform operation**: when a message references an attached/session Asset plus an instruction ("change paragraph", "reformat as bullets"), the Planner routes to a transform step that loads the Asset text, applies the instruction via the LLM, and emits a **new Report Asset** with `version_of` = source Asset and `derived_from` = source Asset. A provenance `Evidence` cites the source (`source_asset_ids` non-empty, P4). The original Asset is never modified (P1). Output is markdown/HTML (binary round-trip deferred).
- This is the Ask-Alfred-fused Editor; a separate Editor mode is not required for MVP.
- **Ingestion** (shared by drag-drop and Library upload/import): Upload (pdf/text/md/docx) and Import-by-URL → parse → chunk → embed → immutable Asset(s). Binary files are stored on the filesystem under the app instance uploads dir; `Asset.storage_ref` points to the file and `Asset.metadata_json` holds extracted text length/page count. Extracted text is chunked into `AssetChunk` rows (NOT the embedding vector table directly) so re-embedding on model change is cheap. Required for RAG even though not a "generated artifact".

### 8. Frontend (Flask + Jinja) — `templates/`, `static/`
- `/alfred/ask`: conversation UI; live updates via polling `/alfred/api/runs/<run_id>/events` (plan + message bubbles + live report preview). Includes a **drag-drop dropzone** that uploads to `/alfred/api/ingest` and attaches the resulting Asset as a chip on the composing message.
- `/alfred/library`: Asset list, upload form, import-by-URL, relations view.
- Reference-back: dropped/attached Assets are sent with the next message as `referenced_asset_ids`; clicking an existing Library item can also attach it. (Literal drag-from-panel-to-message is a UX nicety, not required for MVP.)

### 9. Admin settings (per-app, admin-only) — `admin.py`, `models.py`
- Mirror the existing per-app admin pattern (see `app-radio/devradio/admin.py`, `services/settings.py`): an `AppSetting` key/value table in Alfred's DB + an Alfred admin blueprint (e.g. `/alfred/admin`) guarded by `@admin_required`.
- Settings page lets an admin configure (all consumed at runtime by providers/planner; normal users never see these):
  - `alfred_openrouter_api_key` (encrypted, reuse OpenRouter)
  - `alfred_embedding_model` (e.g. OpenRouter embedding model id)
  - `alfred_agent_model` (ReAct/LLM model id)
  - `alfred_react_max_steps` (per-phase step budget)
  - `alfred_chunk_size`, `alfred_chunk_overlap`, `alfred_top_k` (RAG retrieval)
- Runtime reads via `get_setting` / `get_setting_int` (port the `services/settings.py` + `crypto.EncryptionService` pattern into Alfred). No model/embedding UI is exposed to non-admin users.
- Surfaced within the existing central admin (same handoff/registration mechanism other apps use); implementation detail is per-app blueprint under Alfred's subpath.

### 10. Provisioning — aligns with the new Runtime Manager / `products.yml` system
The main branch introduced an always-on **Runtime Manager** (systemd `nightcraft-runtime-manager.service`, listens `127.0.0.1:5700`) plus a `products.yml` manifest and a generated nginx `on-demand.conf`. Apps are now registered in `products.yml`; `on_demand` apps are cold-started by the manager on first request and auto-stopped after an idle timeout. **Neera/Artsy is the reference `on_demand` app** — Alfred follows the same contract.

- **Register Alfred in `platform-infra/prod-debian/products.yml`** under slug `alfred`:
  - `public_paths: [/alfred]` (nginx generators emit the `/alfred/` proxy block + `/_nc_touch_alfred` mirror + cold-start `@nc_cold_alfred` + `/_nc_probe/alfred` readiness probe).
  - `runtime.policy: on_demand` (DECIDED — heavy LLM app, intermittent use; idle auto-stop reclaims RAM on the shared VPS and matches Neera/Green Pledge). Switching to `always_on` later is a one-line `policy:` flip in `products.yml`.
  - `runtime.service: nightcraft-alfred.service`, `port: <free port e.g. 5950>`, `upstream: app_alfred_upstream`, `idle_timeout: 30m` (tunable; a longer window avoids restarting during interactive reading).
- **Add `platform-infra/prod-debian/systemd/nightcraft-alfred.service`** modeled on `nightcraft-neera.service` (User/Group `dev`, `EnvironmentFile=/etc/nightcraft/app-alfred.env`, `After=network.target postgresql.service nightcraft-auth.service`, `Wants=postgresql.service`, Gunicorn `--bind 127.0.0.1:<port>`). **Important**: the manager starts/stops this unit, so it must be `systemctl disable`d at install (drop-in `Restart=no`) for `on_demand`; never `enable --now`.
- **Add `platform-infra/prod-debian/scripts/deploy-alfred.sh`** modeled on `deploy-neera.sh`: `setup_venv_and_deps`, ensure `/runtime/shared/app-alfred/instance/uploads/`, `setup-postgres.sh` (Alfred has a DB), and a `flask ... setup` CLI step that creates tables + enables `pgvector`.
- **Add `platform-infra/prod-debian/scripts/seed-alfred-client.sh`** modeled on `seed-neera-client.sh` to seed the OAuth client `alfred-app` (redirect `http://<host>/alfred/auth/callback`) + reuse `devuser`. The auth adapter's callback URL must match.
- **nginx**: no hand-written block needed — `gen-nginx-on-demand.sh` reads `products.yml` and writes `on-demand.conf` (include already wired in `nightcraft.conf`). For `on_demand`, the branded loading page is shown on cold start automatically.
- **Env**: add `platform-infra/prod-debian/env-examples/alfred.env.example` and mirror into `dev-setup/env-templates/service-alfred.env` (`AUTH_MODE`, `AUTH_SERVICE_URL`, `DATABASE_URL`, `REDIS_URL`, `OPENROUTER_API_KEY` — though the key is admin-set via `AppSetting`, keep an env fallback).
- **Dev environment**: prefer adding `app-alfred` to the existing `dev-setup/docker-compose.yml` (postgres + redis networks) for local iteration, rather than the prod on_demand flow. The on_demand wiring is prod-only; local dev can run Alfred directly.
- **pgvector**: enable on Postgres 16 (`ankane/pgvector` image or `CREATE EXTENSION vector` in init). Same as before; now also ensure `setup-postgres.sh`/Alfred setup enables it.
- Reuse `seeduser`/`devuser` per deployment conventions.

### 11. Idle-timeout rehydration (keepalive) — DECIDED: app-driven via existing `/touch`
The Runtime Manager stops an `on_demand` service when `now - last_access > idle_timeout`, and `last_access` is refreshed **only** by nginx's `mirror /_nc_touch_alfred` on each HTTP request. There is no "actively working" concept, so a long Alfred agent run survives *only* while the browser keeps polling. We must keep Alfred alive while the user is active **without modifying the shared manager** (used by Neera/Green Pledge).

Contract:
- **Browser heartbeat**: the Alfred frontend calls `GET /alfred/api/heartbeat` every ~15s while the tab is open (lightweight, no heavy work). Each call passes through nginx and re-mirrors `/_nc_touch_alfred`, refreshing `last_access`. Covers "user is reading/editing but not polling a run."
- **Backend run-keepalive**: while an `AgentRun` is in `running` state, Alfred's own backend holds a timer (e.g. every 20s) that calls `POST http://127.0.0.1:5700/touch/alfred` directly (bypasses nginx). This is the real rehydration: even if the browser is closed/backgrounded or a slow LLM call runs with no client polling, the service stays up until the run completes. Stop the timer when the run reaches `done`/`error`.
- **Idle only when truly idle**: the sweep will now only fire when there are no recent requests, no heartbeat, AND no active run — i.e. the user has genuinely walked away.
- **Intervals** must be well under `idle_timeout` (30m) — 15–20s is more than safe; they just need to beat the 30s sweep + 30m idle window.
- **No shared-infra change**: reuses the existing `/touch/<slug>` endpoint and the existing `mirror` directive already emitted by `gen-nginx-on-demand.sh`. Future enhancement (not MVP): add an explicit `/keepalive/<slug>` lease to the manager so it understands "busy" natively; not required now.

### 12. API contract & auth wiring (grounded in live `app-artsy/neera`)
These details are required so Alfred's SSO + API match what the seeded OAuth client and `@auth_required` guards expect.

- **Auth adapter must replicate Neera's exact SSO blueprint** (so the seeded `alfred-app` client works):
  - Blueprint `url_prefix="/auth"` with routes `/login`, `/callback` (`authorize_access_token` → `userinfo` → `session["user_id"]`), `/logout` (POST), `/register` (→login).
  - `init_sso(app)` registers the Authlib OAuth client from env `AUTHLIB_CLIENT_ID` / `AUTHLIB_CLIENT_SECRET` (set in `app-alfred.env` to `alfred-app` / the seeded secret) and `AUTH_SERVICE_URL`.
  - In SSO mode, a `before_request` bridge (`ensure_session_from_shared_auth`) populates `session["user_id"]` from the shared auth cookie — identical to Neera.
  - `seed-alfred-client.sh` seeds client `alfred-app` with redirect `http://<host>/alfred/auth/callback`, which must resolve to the `/auth/callback` route under the `/alfred` prefix.
- **All API endpoints use `@auth_required`** (mirror `app-artsy/neera/guards.py`) and resolve the acting user via `get_current_user().user_id`. Endpoints:
  - `POST /alfred/api/runs` → create `AgentRun` (status `queued`), kick the executor in a **background thread** (returns immediately with `{run_id}`); the agent runs in-thread with `app.app_context()`.
  - `GET /alfred/api/runs/<run_id>/events` → ordered `RunEvent` rows for that run, **scoped by `user_id`**; powers the polling live UI.
  - `POST /alfred/api/ingest` → upload file → immutable Asset (drag-drop + Library upload), `user_id`-scoped.
  - `GET /alfred/api/heartbeat` → 200 no-op; auth-guarded so only logged-in users keep Alfred alive (prevents anonymous keepalive abuse). Passes through nginx and re-mirrors `/_nc_touch_alfred` (§11).
  - `POST http://127.0.0.1:5700/touch/alfred` → backend run-keepalive (§11); server-to-manager, no app auth.
- **App config**: `app.config.from_prefixed_env()` (like Neera) so `app-alfred.env` keys map naturally; plus `AUTH_MODE`, `AUTH_SERVICE_URL`, `DATABASE_URL`, `REDIS_URL`, `OPENROUTER_API_KEY` (env fallback for the admin-set key).
- **Admin blueprint** `/alfred/admin` guarded by `@admin_required` (requires `AppUser.is_admin`); model/embedding controls are absent from all user-facing UI.

### 13. Dependencies & env conventions
- **`requirements.txt`** (Alfred-specific — Neera's is minimal and does **not** include these; do not assume they're present): `Flask`, `Flask-Login`, `Flask-SQLAlchemy`, `authlib`, `psycopg[binary]`, `gunicorn` (prod WSGI), `langgraph` + `langchain-core` (planner/executor), `openai` (OpenAI-compatible SDK pointed at `base_url="https://openrouter.ai/api/v1"` for both chat + embeddings), PDF/text parsing: `pypdf` (PDF), `python-docx` (.docx), `beautifulsoup4` (web import). Pin like Neera (`Flask==3.1.1`, etc.) where possible. `redis` is **optional** (see below).
- **Env key convention** (matches Neera + `app.config.from_prefixed_env()`): `FLASK_AUTH_MODE`, `FLASK_AUTH_SERVICE_URL`, `FLASK_AUTHLIB_CLIENT_ID`, `FLASK_AUTHLIB_CLIENT_SECRET`, `FLASK_SECRET_KEY`, `FLASK_UPLOADS_DIR`, `DATABASE_URL`, `REDIS_URL` (optional), `OPENROUTER_API_KEY` (env fallback only; the active key is admin-set in `AppSetting`). Alfred-specific admin settings live in `AppSetting` (DB), not env.
- **Redis is optional**: Alfred's run state, `RunEvent` stream, `AgentRun`, and the LangGraph checkpointer all live in **Postgres** by default — no separate Redis service is required for MVP. Redis may be added later for a job queue, but provisioning should not depend on it. (Radio uses Redis; Alfred does not need to.)
- **Stale file (note, out of Alfred scope)**: `dev-setup/env-templates/app-seeksage.env` remains after SeekSage removal. Leave it or remove separately; do **not** base Alfred on it.

### 14. Failure modes & lifecycle
- **Provider errors (LLM / embeddings / web search)**: wrap each provider call in try/except; on failure emit an `EVT_*_ERROR` RunEvent and either retry (bounded) or mark the phase/run `error` with a user-visible message. Never leave a run stuck in `running`.
- **Partial ingestion rollback**: ingest is transactional per Asset — if parse/chunk/embed fails mid-way, roll back the Asset + its chunks/embeddings (or mark failed) so the Library never shows a half-indexed Asset. `content_hash` dedupe prevents duplicate re-ingest; allow re-ingest of failed Assets.
- **Stuck/abandoned runs**: a run whose worker is killed (e.g. on_demand stop, crash, unhandled exception) may stay `running`. Add a startup sweep that marks any `running` run from a prior process as `error`/`interrupted`; the polling UI shows a recoverable state. The keepalive (§11) prevents stopping a *live* run, but a crash still needs cleanup.
- **Embedding dimension mismatch**: `AssetEmbedding` stores the model id per row; `library_search` compares only vectors whose `model` equals the active `alfred_embedding_model` setting. On admin model change, the "Re-index library" action re-embeds all chunks; the pgvector index is re-created for the new dimension. Old-model vectors are excluded from search until re-indexed.
- **Asset / file deletion**: deleting an Asset removes its chunks + embeddings + the backing file (`storage_ref`) in one transaction and cascades relations. Reports/versions that reference it remain (provenance is historical); mark dangling references. Hard-delete only for MVP.
- **SSO session edge**: in SSO mode the `before_request` bridge must tolerate a missing/expired shared session (treat as anonymous → redirect to login), same as Neera — never 500.

## Validation
- **Unit (pytest, reuse `pytest.ini` pattern from app-note/app-artsy)**:
  - Asset dedupe by `content_hash`.
  - Evidence rejected when `source_asset_ids` empty (P4).
  - `library_search` returns results with valid `source_asset_ids` **and only for the requesting `user_id`** (per-user isolation).
  - Planner emits valid phase plan; executor routes to `library_search` when library has the answer and to `web_search` when it does not.
- **Manual**: ingest 2 docs as user A → ask a question answerable only from the library (verify RAG path + citations) → ask a question requiring the web (verify non-RAG path) → confirm Report appears in Library as a new Asset with `derived_from` relations → log in as user B and confirm the 2 docs and the Report are NOT visible/retrievable (isolation).
- **Failure**: (a) force an embedding/LLM error mid-run → run ends `error` with a visible message, never stuck `running`; (b) kill the worker mid-run → on next start the run is marked `error`/`interrupted`; (c) ingest a corrupt/unsupported file → Asset marked failed, re-ingestable, Library never shows a half-indexed Asset; (d) change `alfred_embedding_model` → old-model vectors excluded from search until "Re-index library" runs; (e) keep a tab open during a long run and let the app go idle otherwise → backend run-keepalive prevents the manager from stopping Alfred (§11).

## Risks / open items
- **OpenRouter embeddings**: confirmed available via OpenAI-compatible `/api/v1/embeddings` (models: `openai/text-embedding-3-small`, `qwen/qwen3-embedding-8b`, etc.). Default `openai/text-embedding-3-small` (1536-d). Embedding model id is admin-configurable. **Caveat**: changing the embedding model (or its dimension) requires re-embedding the library — add an admin "Re-index library" action that re-runs ingestion embeddings over existing `AssetChunk` rows.
- **pgvector on Alpine**: must use a pgvector-enabled image or install the extension — explicit provisioning step.
- **Cost/latency**: hybrid planner adds one LLM call per goal; enforce `max_steps` budgets from admin settings.
